# Contractor credential layer — Founder review packet

Prepared from builder `9eabfb7` and independent Evidence certification. Branch preview only; no production publication or mutation.

## Architecture decision

The existing `licenses` table already has `contractor_id UUID NULL`, a source-scoped unique key `(source_system, external_key)`, source statuses, a raw payload, and batch provenance. It can hold the 12,792 license/credential records below without creating `contractors` or `entities`. The current Verify and profile queries inner-join `licenses` to `contractors`, so unattached rows are invisible there. A separate credential lookup/result type is required before publication; reusing `SearchResult` or `ResultCard` would imply a contractor profile and link to `/contractors/[slug]`.

`permit_records` describes property permits with jurisdiction/address keys and activity joins. NJ DFS business permits are not property permits. They remain in the certified staged/row-level evidence artifact until a permit-evidence surface or appropriately scoped row store is reviewed. `ingest_batches` can hold source provenance, not the 542 permit rows themselves. No schema change is proposed in this branch.

`CANONICAL_BUSINESS` remains a `contractors` row supported by separate identity authority. `BUSINESS_LICENSE / CREDENTIAL` is an unattached `licenses` row with its source-native key. `SOURCE-NATIVE BUSINESS LICENSE` is the ZA subclass of that grain, not a distinct canonical legal entity. `PERSON_CREDENTIAL` remains held. `PERMIT_EVIDENCE` is an NJ source record; it is neither a `contractors` row nor a property permit.

## Proposed later publication, subject to Founder review

1. Reverify the frozen source hashes in `classification-counts.json` and live exact ownership. Stop on count, key, class, or status drift. Preserve raw source fields and `ingest_batch_id`.
2. Load only the 12,792 eligible credentials into `licenses` with `contractor_id = NULL`. Use source-scoped deterministic `external_key`; mold requires **license type + license number** because 28 numbers recur across types. The source label and holder display text are not entity-bridge authority. No `contractors`, `entities`, or `contractor_entities` inserts.
3. Add a separate credential lookup result and detail surface that queries unattached licenses by exact/prefix native key, then bounded name text for discovery. Display source, jurisdiction, class, native number, raw status, and observation date. Its result type must not contain a contractor slug or imply a verified legal entity. Do not add these rows to browse/business counts or the current canonical `SearchResult` query.
4. Keep all 542 NJ rows in permit-evidence staging pending a separately reviewed row-level evidence surface. A source card may show the certified count and PDF link; no active-business count or entity attachment follows from the PDF.
5. Person-only records remain in `person-credential-hold.csv`. No person profiles or qualifier-to-business links are created.

This gives exact credential lookup and specialist-search recall after the separate surface is approved. Regulatory evidence can be shown at its source grain. Canonical business search and counts do not change. No current Contractor page should show an unattached credential as if it were an exact company attachment.

## Preview and acceptance checks

`credential-layer-preview.json` is generated by `python scripts/contractor_credential_preview.py`. Each example has a source-grain label, source-native key, raw-status-derived label, and `canonical_business_id: null`. It is a local preview, not a public route. The generator rejects missing/duplicate source keys and count drift.

Required Founder gate checks: source hash and count, source-scoped key uniqueness, exact live ownership, null contractor attachment, status distributions, no person rows, no property-permit reinterpretation of NJ, and before/after `contractors` count equality.
